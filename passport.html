Secure connection · how a wireless reading earns trust

From methodology tools to passport.

Quality readings travel over encrypted BLE and Wi-Fi links to a controlled backend, never through a chat. The App only ever receives the approved result and a reference to the evidence.

Tamper-evident, not tamper-proof
01 · Context

Operator + task

Verified employee, a server-issued station session and the exact part and operation.

02 · Transmit

BLE + Wi-Fi link

The gauge sends its signed reading over paired BLE to a gateway, which forwards it on encrypted Wi-Fi.

03 · Verify

Evidence gateway

Check signer, paired device, session, freshness and duplicates. Failures go to quarantine.

04 · Preserve

Evidence vault

Originals locked for the retention period. Events are only ever appended.

05 · Decide

FDM Quality

Inspection, final QC and assessor decisions. Nothing is silently overwritten.

06 · Display

Skill Passport

Shows skill evidence and employer-issued status. Raw data stays controlled.

Transport + identity

Two identities. Two doors.

  • BLE instruments pair with LE Secure Connections and bond to one gateway
  • Wi-Fi devices use WPA3-Enterprise, certificates and mutual TLS
  • App users get short-lived sessions for one factory
  • A user session can never submit device evidence
  • No secrets or private keys inside the App
Confidentiality

Keep the raw data private.

  • Encrypted over the air and at rest
  • Every view and file is permission-checked
  • Shared passports hide drawings, part IDs and raw scores
  • Screenshots can’t be fully prevented on every device
Before production

Prove the trust boundary.

  • Test BLE pairing, Wi-Fi security, key storage and firmware
  • Test identity binding and offline behaviour
  • Agree retention, deletion and the China data model
  • This prototype is not a security certification

What the factory device signs

Never sign just “PASS”.

Every inspection is sealed with its full context, so nobody can quietly change it later:

schema versiontenant / sitedevice IDboot epochsequenceevent + capture IDscapture timework sessionpart instancework orderrevisionoperationparticipant rolesfeature IDvalues · units · limitsinstrument resulttransport + pairing IDcalibration refhashes of originals

The server adds its own signed receipt. It never rewrites the signed bytes.

Tip: the FDM feature ID is a permanent identifier, not a balloon number, so renumbering a drawing never breaks the evidence chain.
A pass rate is not a skill score.

Part outcomes also depend on the machine, material, tooling, gauge and task difficulty. Start with traceable task experience and assessor-reviewed observations; formal qualification needs an approved assessment process.

Implementation fit: reuse ConnectIQ’s shared REST / .NET services and SQL data model where it fits. Check SQL Server / Azure SQL Ledger support for your actual deployment before relying on it. One logical product does not require copying every customer’s raw data across borders.
