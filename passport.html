Live local cryptographic demonstration

Change the result. Break the signature.

This lab really signs sample bytes with Web Crypto (ECDSA P-256 / SHA-256). It is not the simulated verification used in the phone. Keys and replay tracking exist only in this page; there is no production trust anchor.

Ready. No keys or inspection data leave this page.
Image hash: not generated

The image bytes are a synthetic text fixture, not a camera frame. The demo signs exact serialized bytes (formatting changes also invalidate the signature); production should use a tested signing format such as JWS and an agreed canonicalization policy. After one successful ingestion, verify the same event again to see duplicate rejection. Re-signing resets this local lab.

Controls that the UI cannot provide

What each control actually protects.

Changed result, image or operator field

Verify the digital signature and image digest, including job, part, station and session in the signed payload. A hash stored beside an editable image is insufficient.

Authentic event, replayed for another reward

Persist unique event IDs, device sequence / boot epoch and consumed challenges on the server. Idempotent retries return the first receipt; never count twice.

Administrator edits a past decision

Keep immutable originals and append a signed amendment. Independently protect audit checkpoints; an ordinary SQL row lock is not an integrity guarantee.

Valid signature, wrong physical work

A signature cannot prove the correct part was placed in the camera or the named employee did the work. Bind fixture / part identification, cycle trigger, work session and observed roles.

Legacy camera has no signing capability

Sign on a hardened edge gateway at first trusted receipt. Display “gateway-verified,” not “camera-origin verified.” The camera-to-gateway path remains a trust boundary.

Connection drops or camera time changes

Queue signed records on the edge. Show “pending server verification,” preserve capture and receipt times separately, and investigate sequence gaps or counter resets.

Transport + identity

Two identities. Two API surfaces.

Use enrolled device certificates and mutual TLS for the edge. Use short-lived, tenant-scoped user sessions for WeChat. A user session cannot call the device evidence ingestion API. Never embed AppSecret, device private keys or shared signing secrets in a Mini Program.

Confidentiality

Keep the raw image private.

Encrypt objects at rest. Authorize every view and evidence object. Use an authenticated media proxy or carefully scoped short-lived URLs. Shared passport views exclude customer drawings, part IDs and employee raw performance data by default. Screenshots cannot be reliably prevented.

Before production

Validate the trust boundary.

Test camera interface, key storage, firmware controls, identity binding, offline behavior, model validation and deletion / retention policy. Decide the China deployment and data-transfer model explicitly. No feature in this wireframe constitutes a security certification.

What the factory device signs

Never sign just “PASS”.

Every inspection is sealed with its full context, so nobody can quietly change it later:

schema versiontenant / sitedevice IDboot epochsequenceevent + capture IDscapture timework sessionpart instancework orderrevisionoperationparticipant rolesfeature IDvalues · units · limitscamera resultmodel / recipe versioncalibration refhashes of originals

The server adds its own signed receipt. It never rewrites the signed bytes.

Tip: the FDM feature ID is a permanent identifier, not a balloon number, so renumbering a drawing never breaks the evidence chain.
Before the pilot

Try to break it first.

Each of these should fail loudly and visibly, not silently.

Identity + access5 tests
  • Forwarded or expired QR
  • Role escalation
  • Ex-employee still logged in
  • Another factory’s evidence ID
  • Stolen account recovery
Evidence + integrity6 tests
  • Edited result or image
  • Replayed signed event
  • Revoked device key
  • Deleted record
  • Swapped part
  • Changed model recipe
Quality + assessment5 tests
  • Valid signature on a failed part
  • Final QC reversed
  • Operator reassigned
  • Expired qualification
  • Supervisor tries to edit raw evidence
Operations + onboarding6 tests
  • Lost connection
  • Half-finished upload
  • Sequence gap
  • Counter reset
  • Time to first task
  • Time to first accepted evidence
A pass rate is not a skill score.

Part outcomes also depend on the machine, material, tooling, gauge and task difficulty. Start with traceable task experience and assessor-reviewed observations; formal qualification needs an approved assessment process.

Implementation fit: reuse ConnectIQ’s shared REST / .NET services and SQL data model where it fits. Check SQL Server / Azure SQL Ledger support for your actual deployment before relying on it. One logical product does not require copying every customer’s raw data across borders.
